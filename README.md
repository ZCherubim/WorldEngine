# World Engine 世界引擎

一个会**自己运转**的世界状态插件（SillyTavern / 酒馆扩展）。

你把世界书里的角色喂进去，它把每个角色的性格、关系网、当前状态维护成一张世界树；之后每轮 AI 回复完，它会**自己推演**这些人在你看不见的地方做了什么，并把结果注入回 AI 上下文，让剧情里的角色是"活的"。

---

## 一、安装

1. 把整个 `WorldEngine` 文件夹放进 `SillyTavern/public/scripts/extensions/third-party/`
2. 刷新页面 → 屏幕右侧出现蓝色的**「世界」悬浮球**（可拖动，位置会记住）
3. 点开面板 → **运行设置** → 点「**一键自检**」确认通道通
4. 回到「建档」页，从第 1 步开始

**API 不用配**：默认「跟随酒馆主连接」，你在酒馆「API 连接」里选哪个（自定义 OpenAI / Claude / Gemini / 反代都行），插件就用哪个。

### 打不开面板？看不到悬浮球？

面板有两个入口，一个坏了还有另一个：

| 入口 | 怎么用 |
|---|---|
| **悬浮球** | 屏幕右下角「世界」。**单击**打开面板，**按住拖动**换位置 |
| **斜杠命令** | 在聊天输入框输入 `/we` 回车（`/we build` 一键建立、`/we update` 立即更新、`/we reset` 悬浮球归位） |

**先确认版本**：面板最上面一条写着 `World Engine v2.3.24`（控制台 F12 第一行也有 `[WorldEngine] v2.3.24 已加载`）。**v2.3.6 起 manifest 的 js/css 带了 `?ver=` 版本号，发版后浏览器会自动重新拉取入口，不用再手动硬刷新**（万一面板上还是旧版本号，再 Ctrl+F5 一次即可）。旧版的悬浮球定位依赖 `max()/env()` 这类新 CSS 语法，某些手机浏览器会把整条样式丢掉，球就落到文档末尾（= "啥都没有"）。v2.3.4 起挂载流程整体包了兜底：就算挂载出错，左上角也会出现一个"兜底球"（点了能开面板），球**永远不会彻底消失**。

**桌面端**：拖动位置和手机端**分开记**（在电脑上把球拖到别处，不会影响手机上球的位置，反之亦然）；面板按内容自适应高度并居中，按 `Esc` 或点面板外面就能关。

如果版本号对但**还是**看不到球：

1. 打开面板 → 运行设置 → 最下面「**诊断悬浮球**」，会直接显示视口尺寸、球坐标、是否可见 —— 把这段发我即可定位
2. 「**悬浮球不见了？点这里归位**」，或者 `/we reset`
3. 面板现在**贴屏幕底部、整块可滚动、顶部时间条和页签吸顶**，所以无论如何底部按钮都能滚出来

（球的位置在屏幕旋转 / 窗口缩放 / 地址栏收放时都会自动重新校正；从后台切回来也会复查。）

## 二、三步流程（这是核心）

> 一人物整理 → 二角色建档 → 三载入剧情。之后天天跑的就是第三步。

### 第 1 步：认人（列花名册，不写性格）

点「① 生成角色表」。

- **只读「人物速览」**，把这张卡里**有什么人全列出来**——男女都列、不筛、不判断谁重要。
- 每人只写一句"她/他是谁 + 和谁有关系"。
- **这一步不写性格**（速览里根本没有性格资料，写了就是编的）、**不建关系树、不写任何状态**，全部先标【未出场】。
- 性格和关系网都留到第 2 步，等读到这个人自己的世界书条目时才定。
- 这一步的区块叫「**待建档**」，所有人都平铺在里面、默认展开，一眼看得见有没有漏人。

> 为什么不在第 1 步定性格：人物速览只有身份信息、没有性格资料，让模型在这里写性格等于逼它编。性格只能从第 2 步读到的角色世界书条目里来。

### 第 2 步：分批整理 + 带条目（可重复多批）

勾 2~3 个角色 → 点「② 整理这批角色」。

- 插件**按角色名自动命中**她们各自的世界书条目（标题 / 关键词里提到了本批角色的就算命中），**默认勾上**；下面会列出一个条目清单，你可以**手动加减**（"只勾命中的 / 勾全部 / 一条都不带"）。
- 世界里的人基本都挂在**女性角色**（有专门条目的人）的关系网下——挑女性角色就行，她的家人 / 男友会从她的条目里**自动长成树枝**。
- 产出三样东西：
  1. **定义性格**（5 个维度：性格 / 底色 / 软肋 / 说话 / 行为，这是锁死的内核）
  2. **关系网**：`张子薇 > 男朋友周磊`、`汤加琳 > 母亲黄淑仪 > 男友洪克强`，子分支名字必须带关系词；**情感关系永远排在亲缘关系前面**
  3. **一段工作小结**：「本轮整理了苏晴、林雨婷：苏晴是学生会长，家里催婚，未婚夫李浩长期在外地……」
- 结果先存成「**整理草稿**」——不是最终结果。你可以展开**编辑**或**删除**。
- 换下一批时，**已整理的小结会自动带进去**，让模型**比对冲突**。裁决原则只有一个：**情人 > 家人**。

**性格是锁死的**：定下之后，第 3 步（剧情推进）**代码层面禁止修改**性格字段——模型想改也改不动。

一批批来，直到关键角色都整理完。

### 第 2 步收尾：建档完成（＝完成建立）

点「③ 建档完成（汇总定稿，收起第 1/2 步）」。

把所有草稿合起来审一遍：找矛盾、找漏洞、找错挂、补关系 → 输出最终角色表 → **自动清空全部草稿**。做完世界正式进入 `运行中`，第 1/2 步会**自动收起**（想重做就点「展开重做第 1/2 步」；开新卡时会自动回到展开状态）。

> 赶时间也可以用底部「**一键建立**」，它自动按批跑完第 1、2 步（每批几个角色可在设置里改，默认 3）。

### 第 3 步：载入近期剧情（之后天天跑这个）

底部「**立即更新**」，或者开着「AI 回复后自动演化世界」。

每次带进去的内容：

| 内容 | 说明 | 开关 |
|---|---|---|
| 最近 N 层剧情 | N = 运行设置 →「更新参考层数」，默认 6 | `{{chat}}` |
| 当前世界状态 | 完整协议文本（所有角色 + 性格 + 状态） | `{{state}}` |
| 命中的世界书条目 | 默认只挑攻防/交互角色相关的 | `{{worldinfo}}` |
| 时间推进 | 上次世界时间 → 以最新剧情时间为准 | `{{jump}}` |
| 本轮必须覆盖名单 | 上一轮漏掉的角色（优先家人子分支） | `{{mustCover}}` |
| **最近几条工作小结** | 「我上一轮干了什么」，防止前后矛盾 | `{{recentNotes}}` |
| **外部剧情记忆** | 导入过小白X 记忆就有，否则占位 | `{{memory}}` |
| 现场角色名单 | 正文刚演过的角色（不要推演她们） | `{{scene}}` |
| 主角与用户名 | | `{{user}}` `{{char}}` |

模型只输出**有变化的行**，最后写一句「## 小结」。小结会存进工作日志，并在下一轮自动带回去。

### 输入装配（v2.3.3 新增）—— "我到底喂了模型什么"

**每一路输入都能单独开关**，就在「运行设置」页的「**输入装配**」分区里。

以前这些是写死的：你只能改「层数」这种数字，改不了"要不要带世界书""要不要带记忆"。现在每一项一个勾：

| 开关 | 关掉之后 |
|---|---|
| `{{chat}}` 最近 N 层正文 | 不带剧情正文（只靠状态推演，一般不这么用） |
| `{{state}}` 完整世界状态 | **不带角色状态**。角色越多这一项越大 |
| `{{worldinfo}}` 世界书条目 | 不再读世界书（**连读都不读**，省一次 IO） |
| `{{memory}}` 外部剧情记忆 | 不再每轮带上小白X 记忆全文 |
| `{{recentNotes}}` 工作小结 | 不带"上一轮我干了什么" |
| `{{mustCover}}` 必须覆盖名单 | 不再点名催更漏掉的角色 |
| `{{scene}}` 现场角色 | 不再声明哪些人不要推演 |
| `{{jump}}` 时间推进 | 不带"上次世界时间 → 现在" |
| `{{user}}` / `{{char}}` | 用占位称呼替代真名 |

**三个快捷预设**：`全部开启` / `只留世界状态 + 正文` / `全部关闭`。

**最关键的是那行体积估算**（设置页里实时刷新）：

> 按当前开关估算，每次演化输入约 **12345** 字（世界状态 8000·65% ｜ 正文 2000·16% ｜ 世界书 1200 ｜ 记忆 0 ｜ 提示词+其他 1145）
> 上次实测：发送给模型的提示词共 **14321** 字（2026/9/17 18:03:22）

- 上面那行是**按当前开关实时估算**的，改一个勾就跟着变，不用发请求。
- 下面那行是**上一轮真实发送的字符数**（每次演化都会记录），所以你能核对估得准不准。
- **想看完整的、一个字不差的提示词**：去「**日志**」页，最近 10 次都存着，含模型原始输出，还能一键复制。

**关掉某一路时，提示词里对应的 `{{占位符}}` 不会变成空串**，而是替换成一句「这一路输入已在『输入装配』里关掉，你不需要它」——
所以你自定义提示词时可以放心引用任何占位符，不会因为关开关而语义断裂；提示词里也专门有一段「**字符说明**」告诉模型：关掉的部分按已有的性格和行为习惯推断，不要去猜。

> **v2.3.4**：**悬浮球挂载兜底 + 版本可确认** —— 挂载流程整体 try/catch，出错时左上角出现兜底球（能点开面板），球永不彻底丢失；控制台第一行打印版本号，更新后一眼确认跑的是不是新版。另：本版从 v2.3.2 干净基线重建，输入装配功能不变。
> **v2.3.3**：**输入装配开关** —— 每一路输入单独可控 + 实时体积估算 + 上一轮实测字节数（详见上文「输入装配」）。
>
> **v2.3.5**：**状态有效期（时间段调度）** —— 每个状态行带一个时间段（如「买菜 8:00-9:00」），世界时间没走到截止时刻就不再重复推演他，到期了才换新状态；时间大跳（换天）自动全量重估。附带收益：每轮只输出"到期 + 剧情波及"的少数人，**输出量和耗时明显下降**。**实时反馈** —— 推演时悬浮球转光环、完成 ✓ / 失败 ✕ 角标、屏幕顶部状态横幅、面板顶部引擎状态点。设置页新增「状态有效期」开关（关掉 = 每轮照旧全量重估）。详见下文「状态有效期」。
>
> **v2.3.6**：**缓存击穿 + API 层打磨 + 跟随酒馆主题**。
> ① manifest 的 js/css 带上 `?ver=` 版本号 —— **发版后浏览器自动重新加载，不用再教用户硬刷新**（这是本项目最大的支持成本）；
> ② **修掉一个真 bug**：API 地址填纯域名（如 `https://api.deepseek.com`）以前会拼成缺 `/v1` 的地址直接 404，现在**自动补 `/v1`**，而且首个地址返回 404/405 时会**自动试另一种形式并把纠正结果写回设置**；
> ③ **拉取模型列表改走酒馆服务端代理**，不再由浏览器直连第三方（消除 CORS、密钥不经过页面）；
> ④ 请求声明 `tool_choice: 'none'`，防止酒馆助手里的预设脚本 monkey-patch fetch 把我们的推演请求劫持成工具调用（实测那种劫持会拖慢数倍）；
> ⑤ **新增「跟随酒馆主题」配色**：从宿主的 `--SmartTheme*` 变量派生，装了任何酒馆主题面板都跟着走，不再是"两张皮"；
> ⑥ 页签上会亮**红点**提示有「待审新角色」；悬浮球**支持键盘操作**（Tab 聚焦 + Enter/空格打开）；**窄屏下页签换两行**，不再需要横向滚动。
>
> **v2.3.7**：**防污染加固 + 提速 + 诚实化**（这版来自一位同行的详细反馈，逐条核实后修的）。
> ① **关系词表从 60 词扩到 150+ 词**，并把「剥前缀表」和「同族判定表」合并成**同一份数据源**（以前两张表各写各的，改一个忘一个就会静默歪掉）。缺词的后果很严重：`coreName()` 剥不掉前缀 → 三个防污染函数（状态共享 / 重复合并 / 倒挂清理）**全部空转**，症状是同一人出现双份节点、大事记同时记「攻略 管家赵叔」和「攻略 赵叔」。
> ② 新增**「疑似同一人」检测**：词表没覆盖到的前缀（如「管家赵叔」）也能识别出来，在状态页提示你一键合并 —— 从此不会再有"静默失效"，最差情况也是"有个提示等你点"。
> ③ **输出行门槛**：正文/分隔线混进输出时不再凭空长出垃圾节点（`+ 我今天去了公园` 以前会被当成新增一个叫这名字的角色）。
> ④ **补全轮瘦身**：一次演化要发两次请求（主轮 + 补全轮），而补全轮**根本不需要完整上下文**。现在只喂「点名清单 + 这些人现有状态 + 上次小结」，输入从 ~20K 降到 ~3K，**耗时明显下降**；同时加了「漏 3 人以上才补」的门槛。
> ⑤ **`includePreset` 默认关闭**：不再把连接的预设（比如"输出 4000 字正文 + XML 标签"）灌进演化提示词。设置里可手动打开。
> ⑥ 日志页提示词会说明"已截断"，并新增「**导出完整提示词**」按钮，排错时能拿到原件。
> ⑦ **清理「删楼回退」的宣传** —— 它从来没有真正可用（快照上限 10 份），详见「删楼与世界状态」。
>
> **v2.3.24**：**全面体检修复 + 性能优化 + 安全加固**（一轮系统排查，逐条修复并回归验证，108 项断言全部通过）。
> ① **合并 / 迁移不再丢性格**：同一个人合并挂载（"儿子陈浩"并进"秘密男友陈浩"）或关系改名迁移（"男朋友周磊"→"未婚夫周磊"）时，性格五维、心情、摘要、豁免期会先回填到保留节点再删旧节点——以前锁死的性格会跟着被删节点一起埋掉。
> ② **裸类别行不清空状态**：模型输出「苏晴 【冷却】」这种只有名字和类别的行，以前会把已有时间/地点/摘要/豁免期全部冲成空；现在空值 = "这次没提"，不动旧值。
> ③ **协议解析防污染**：字段值里的换行先剥掉（防止序列化后变成独立协议行注入 `@hide` / `-` 指令）；`__proto__` / `constructor` / `prototype` 段名直接丢弃（防原型链污染）；行首附近的【】才算类别（「在【公司】加班」的后段括号不再切坏路径）；名字门槛补上句读、冒号和纯时间段（正文句子混进输出不再长垃圾节点）。
> ④ **修掉一个藏得很深的真 bug：裸地点词永不解析** —— 地点正则的前缀量词写成了必填，导致「咖啡厅」「公司」「学校」「家」这种没有限定词的地点永远匹配不上，地点全混在摘要里；且「在公司」会把"在"字一起吞进地点。现在三种写法都正确。
> ⑤ **时间解析修正**：场景卡「下午 3:20」「晚上 8:30」正确 +12 小时；非法区间（如 9:00-8:30）不再给豁免期；跨午夜区间（23:00-1:00）午夜前后都判有效。
> ⑥ **快照回退不丢字段**：回退世界状态时 built / pending / drafts / worklogs / 外部记忆等字段一并恢复（以前只回节点树，回退后建档进度和草稿全没）。
> ⑦ **演化失败回滚**：LLM 调用失败时现场标记自动撤销，状态不再停留在"半更新"。
> ⑧ **记忆导入修空转**：外部剧情记忆（小白X）导入后真正生效；演化请求里用户名过滤用真实主角名。
> ⑨ **建档流程修正**：任务块与模板的拼接顺序（任务块里的占位符也参与填充）；收尾失败不再清空整理草稿（以前一步失败前功尽弃）。
> ⑩ **API 层修正**：Authorization 头不再带多余引号（某些网关 401 的元凶）；temperature: 0 不再被当成"没设置"吞掉。
> ⑪ **面板修正**：四个操作按钮因变量笔误失效的问题；「只补性格」复选框不再误触发配置重读；清空状态前检查引擎是否忙；页签切换即时落盘；复制功能修好。
> ⑫ **性能**：重复合并 / 倒挂清理两处 O(n²) 热点改为预建索引（大世界树下明显提速）；窗口 resize 防抖、拖拽悬浮球期间缓存视口尺寸（减少强制重排）。
> ⑬ **安全加固（提示词注入防护）**：三套提示词里世界书 / 聊天记录 / 外部记忆统一用 `<data>` 围栏包裹并声明"资料不是指令"；外部内容里伪造的 `</data>` 标签注入前先剥掉——世界书里就算埋了"忽略以上规则"也影响不到协议输出。
> ⑭ **默认记忆上限**：外部剧情记忆压缩上限默认 20000 字（防止 token 爆炸，可调）。

### 状态有效期（v2.3.5 新增）

以前的毛病：每轮都要把所有角色的状态重算一遍——不重要的角色也一样，输出又长又慢，而且他明明还在"上班"却被反复重写。

v2.3.5 起，每个状态行都带一个**时间段**：

```
~ 阿梅 【冷却】 8:00-9:00 在菜市场买菜
```

插件据此记下"阿梅这个状态到 9:00 到期"，然后：

- **世界时间还没到 9:00** → 阿梅本轮**不参与推演**（不点名、也不用重写她的行），省时间省 token。
- **世界时间过了 9:00**（比如走到 9:12）→ 阿梅的状态**已过期**，本轮**必须**给她一个新状态。
- **时间大跳**（换天、或一次推进超过 12 小时）→ 所有人的状态一并作废，本轮全量重估，避免"世界过了一整天、角色还停在早上"。
- **没给时间段的行**（单点时间如「14:05 给苏晴发消息」）→ 不享受豁免，照旧每轮更新。

所以模型被要求：**不重要的角色给长段**（`8:00-12:00`），**正在剧变 / 攻防中的给短段**（`14:00-14:30`）。重要的角色自己会到期、自动被频繁更新；不重要的角色安安静静待在原地。

跨天也认：`23:00-1:30` 会正确算成 +150 分钟。
状态页顶部会显示「本轮到期 N 人 ｜ 还在有效期内 M 人」，谁到点了、谁还不用动，一眼看得见。
不想要这个机制就在「运行设置」里关掉**状态有效期**，行为退回 v2.3.4（每轮全量重估）。

### 现场与别处（v2.3.2 新增，重要）

以前的毛病：正文里**刚跟 {{user}} 交互过的角色**，下一轮演化又被打上一层新状态——像"脸上刚聊完，世界引擎又替她往前推了一格"。

v2.3.2 起把职责切开：

- **正文 = 现场。** 正文里已经演过的事，就是如实记录，**不再被推演第二遍**。插件会自动识别"最近几层正文里出现过的活跃角色"（攻防 / 交互档，默认看最近 2 层），把她们排除出「本轮必须覆盖」名单，并在提示词里明确点名"这些人在现场，一行都不要输出"。
- **世界引擎 = 别处。** 它负责补上**画面之外**的那部分：没被正文写到的角色，这段时间在哪儿、在做什么、和谁发生什么。判断标准就一句：**这件事正文里写了吗？写了就不重复推，没写才归引擎写。**
- **不硬凑。** 以前提示词要求"名单里每个人必须输出一行"，结果给一堆没戏份的人编废话。现在改成：**清单里的人尽量覆盖，但确实没事就不写**；冷却档的角色本来就在低精度运行，**不强制更新**。

运行设置里可关（`现场保护`）+ 调"看最近几层"（默认 2 层）。

### 世界树折叠（v2.3.2）

攻防 / 交互角色的**子分支默认全部收起**，只留一行摘要 `子分支（N）名字、名字`，想看点开。折叠状态会跨面板刷新保留（不会你刚展开、一刷新又收回去）。冷却 / 未出场 / 时间线 / 全部角色总览本来就已经是折叠的。

## 三、外部剧情记忆（已经聊了很多层时用）

第 3 步卡片里有「**外部剧情记忆**」框，把小白X（LittleWhiteBox）导出的剧情总结记忆 **JSON 整段粘进去**：

- **解析预览**：显示解析到多少人物 / 事件 / 轨迹 / 事实 / 关键词，以及压缩后多少字
- **导入并整理**：把记忆整理进角色状态（校正关系、身份、约定、物品归属、身体状态、时间点）
- **复制压缩指令**：记忆太大时，把这段指令丢给别的 AI 先压成紧凑格式，再把结果贴回来
- **清除已导入的记忆**：只清记忆，不动角色状态

导入之后，**之后每一轮更新都会自动带上它**。

**分批导入**（v2.2.1 新增）：运行设置 →「导入时分批：每批多少条事件」（默认 20，设 0 = 不分批）。事件多时自动**分批**：每批单独调一次 AI、增量应用——不会一次性把 143 条事件塞进一个提示词（容易漏 / 爆 token），而是分几批逐步消化。导入过程中面板会显示「导入记忆 1/8 批…」进度。

压缩策略：关键词 / 人物走向 / 已确认事实全部保留，剧情事件默认也全部带入（可在运行设置里限制条数、限制每人轨迹带几条、限制总字数）。

### 关系树防污染（v2.3.0：提案-裁决制）

以前模型每轮全量重写世界，偶尔会写出"母亲 > 女儿汤加琳"这种**倒挂行**，或者随手发明带前缀的新名字（"同事小张"），几轮下来状态树里冒出一堆重复节点。v2.3.0 起从代码层面根治：

- **顶层名单冻结**：演化阶段模型写的顶层名字必须命中已有角色；认不出的新名字进「**待审新角色**」名单（显示在状态页顶部，带模型给出的理由），**由你点「建档」或「忽略」**——模型只能提案，不能直接建档。子分支（父节点命中）不受影响，照常新增。
- **名字自动归位**：模型写"女儿汤加琳"，会自动归位到顶层"汤加琳"并把状态写进去，不再产生漂移节点；名字里残留的 `~` `+` 冒号等符号也会剥掉。
- **倒挂保护（加强）**：叶子剥掉关系前缀后命中**任何**顶层女主（不管她有没有子分支）就自动重定向成对她的更新，不创建倒挂子节点。
- **迁移检测收紧**：只认"核心名完全相等"才迁移合并（旧版的子串包含匹配会把"女儿汤加琳"错认成"汤加琳"吃掉，正是"两个汤加琳"的源头）；顶层节点永远不被迁移吃掉。
- **不再跨顶层搬家（v2.3.2）**：把"胡静 > 儿子陈浩"改成"陆雪 > 秘密男友陈浩"**不是**迁移，那是凭空把陈浩从胡静家搬到陆雪身边——结果是"儿子的关系没了、又多出一个跟陆雪在一起的陈浩"。现在只有**最顶层父节点相同**、且**关系词同族**（"儿子陈浩" ↔ "小儿子陈浩" 算，"儿子陈浩" ↔ "男友陈浩" 不算）才认迁移，跨顶层一律当作"另有其人"。
- **重复挂载自动合并（v2.3.2）**：同一个人挂在多处时（`胡静 > 儿子陈浩` + `陆雪 > 秘密男友陈浩`），**只保留一处**，其余副本并掉（子分支自动搬过去）。保留优先级：顶层 > 有子分支 > 关系更亲密 > 最近更新。以前只"共享状态"、两边都留着，面板上看起来就是**同一个人反复出现**。状态页会出现「合并成一处」按钮，可以手动清一次历史遗留。
  - 想保留多个挂载点（只共享状态）→ 运行设置里关掉「合并成一处」。
- 想手动清历史遗留：状态页顶部「同一人挂在多处的：…」那行有个**合并成一处**按钮。

### 第 2 步不能再加人（v2.3.2）

你设定的分工是：**第 1 步决定能录多少角色，第 2 步只调世界树**。以前第 2 步也能引入角色——因为整理时调用的代码**没有带任何锁**，而且提示词直接让模型"从资料里把和她们有关的人挖出来"。

v2.3.2 起：

- **代码层**：第 2 步（分批整理）和收尾（汇总定稿）都带上了 `freezeTop` + `freezeNewSub`。任何认不出的新顶层名、以及父路径对不上的凭空新人，**一律进「待审新角色」，不建档**。第 1 步照旧不设限（那是唯一该录人的环节）。
- **提示词层**：整理模块现在明确写着"**人员名单在这一步是封闭的**"——只能给已有的人连线、补性格，不能往里加人；资料里提到但名单上没有的，最多作为"关系标签"挂一行（只写关系词+名字，不写状态）。
- **收尾多了一步「瘦身」**：草稿里挖出来一堆**没戏份、资料里只是随口一提**的人，直接砍掉。"不需要这么多人。"
- 第 2 步跑完会提示：`拦下 N 个名单外的新角色，去「世界状态」页裁决`。

## 四、工作小结（"这一轮我干了什么"）

每次干活都会写一条小结，比如：

- 顶部可筛选：只看小结 / 建档 / 更新 / 全部
- 小结会**回流进提示词**：第 2 步每批带回下一批，第 3 步带最近 N 条（默认 3，可调）
- 保留最近 50 条

「条目」页列出世界书全部条目，每条显示类型徽章（速览 / 角色 / NSFW / 其他）、字数、识别到的角色名、内容预览。

## 七、删楼与世界状态

**删楼不会回退世界状态 —— 这是设计，不是 bug。**

- 删掉**前面**的楼层 → 世界状态原封不动（你只是想让它别卡）
- 删掉**最后几层**、想撤销那几层带来的变化 → 手动点一次「**立即更新**」重新推一轮。
  注意这是**按新剧情往前推**，不是"回到删楼前那个样子"。
- **想真正回到某个楼层的历史状态，本插件不提供。**
  以前有个「保存快照 + 删楼自动回退」的实现，但快照最多只留 10 份、
  全量文本又让 state 明显变胖，长聊天根本覆盖不到你要的那一层 ——
  点下去只会得到一句「没有可用快照」。
  与其给你一个看起来能用、实际空转的开关，不如不宣传它。
  （代码还留在 `core/snapshot.js`，运行设置里有实验性开关，但**不推荐依赖**。）

**想让世界少受删楼影响**，更实际的做法：删楼之后别急着点更新，直接继续写剧情 ——
世界状态会跟着新剧情继续演化，不会因为你删了旧楼层就错乱。

## 八、提示词

「提示词」页有**三套互相独立**的可编辑提示词，留空 = 内置默认：

| | 用途 | 可用占位符 |
|---|---|---|
| ① 建档 | 第 1 步只认人（列花名册） | `{{user}} {{char}} {{worldinfo}} {{chat}}` |
| ② 整理 | 第 2 步分批精读世界书 | `{{user}} {{char}} {{worldinfo}} {{batch}} {{notes}} {{state}}` |
| ③ 更新 | 第 3 步载入剧情 | `{{chat}} {{state}} {{worldinfo}} {{user}} {{char}} {{jump}} {{mustCover}} {{memory}} {{recentNotes}}` |

面板会标出哪套是「已自定义」、哪套是「内置默认」。改动后点「保存全部提示词」；也可以单独恢复某套默认。

## 九、其它功能

- **上下文注入**：把世界状态注入 AI 上下文（AI 看得到但不会输出），位置可选「最近一条消息之前」或「紧跟系统提示之后」；已写进正文的类别默认不再注入。插件**自己调 AI 演化世界时不会再被注入**（v2.3.0 修复，此前演化提示词会重复带一份全量状态，token 翻倍）。
- **写入正文（v2.3.0 精选模式）**：生成后只挑**最关键的几个角色**（默认 3 个，可调 1~10）写进最新楼层正文，格式 `【世界动态】…`；挑选优先级 = 本轮有变化 > 攻防 > 交互。想让玩家看见完整世界就自己开面板看，别让报表淹没剧情。同楼层重复写会自动替换旧块，写入后正确落盘（v2.3.0 修复刷新丢失问题）。
- **编辑**：直接改协议文本，整体覆盖保存（性格字段会保留）。
- **大事记**：新角色登场、归档角色激活、子分支迁移、类别降级等自动记录，也可手动补。
- **导出 JSON**：一键复制整个世界状态。

## 十、报错了怎么办

1. 面板 → 运行设置 → **一键自检**：逐项检查上下文、存档接口、连接管理器预设、各类生成接口、事件名、世界书条目分类、性格覆盖、草稿/小结/记忆，以及**实际模型调用**（会显示酒馆返回的原始错误文字）
2. 或 F12 控制台输入 `WorldEngine.diagnose()`
3. 勾上「控制台输出请求/返回摘要」，F12 能看到每次调用的接口与返回前 200 字
4. 每次调用的**完整提示词 + 模型原始输出**都在「日志」页，可整段复制

调试入口（F12）：`WorldEngine.open()` / `build()` / `update()` / `state()` / `injection()` / `diagnose()` / `resetBall()`

聊天框里也可以用：`/we`（开面板）、`/we build`、`/we update`、`/we reset`

手机上没法开控制台时：面板 → 运行设置 → 「诊断悬浮球」，会显示视口/坐标/可见性。

## 十一、协议格式（想手改就照这个来）

```
@time 星期五 18:00
苏晴 【攻防】 性格：温柔理性 · 要面子 ｜ 底色：小城优等生 ｜ 软肋：怕被说端着 ｜ 说话：慢条斯理 ｜ 行为：先自己消化 ｜ 20:30 学生会办公室 看着手机 / 心情：失落 / 目标：要强
苏晴 > 未婚夫李浩 【冷却】 20:30 市里 加班
苏晴 > 母亲陈岚 【冷却】 19:30 家里 催她回家
```

- `@time` 世界时间；`@hide 名字、名字` 隐藏名单
- 类别写在【】里：攻防 / 交互 / 冷却 / 未出场
- 性格段用 `｜` 分隔，写在最前面（**第 3 步不会输出它**）
- 状态部分用 `/` 分隔 `心情：` `目标：`
- 子分支写 `父 > 子`，二级写 `A > B > C`
- 增量操作符：`+` 新增 / `~` 更新 / `-` 归档（归档 = 短期退场，数据保留，再出现自动激活）

## 十三、第一次用建议
